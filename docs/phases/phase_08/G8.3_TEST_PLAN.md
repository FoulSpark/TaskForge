### 1. Test Harness Architecture & Subprocess Isolation

To satisfy the engineering requirement that tests must validate **actual operating system process terminations** rather than mocked exceptions:

1. **Subprocess Invocation:** Tests launch real OS processes via Python's `subprocess.Popen` running:
   ```powershell
   .\.venv\Scripts\python.exe -m taskforge.workers.dispatcher --worker-id <unique-id> --concurrency <n> --grace-period <seconds>
   ```
2. **Environment Variable Injection:** Each spawned worker process receives:
   - `DATABASE_URL`: `postgresql+psycopg://taskforge:taskforge_dev@localhost:5432/taskforge_test`
   - `REDIS_URL`: `redis://localhost:6379/0`
   - `APP_ENV`: `test`
   - `BROKER_TYPE`: `redis`
3. **Operating System Signal & Process Kill Semantics (Windows 11 AMD64):**
   - **Abrupt Kill:** `proc.kill()` invokes the Win32 `TerminateProcess()` API. The process halts immediately without executing `finally` blocks, `atexit` hooks, or signal handlers.
   - **Graceful Termination:** On Windows console processes, tests trigger graceful termination by sending `signal.CTRL_C_EVENT` or invoking `dispatcher.stop(grace_period_seconds=...)` in an orchestration harness.
   - All tests must cleanly clean up child processes in `try...finally` or fixtures using `proc.poll()`, `proc.kill()`, and `proc.wait(timeout=5)`.

### 2. Calibrated Test Timing Configurations

To ensure fast, deterministic automated test execution without waiting 30–60 seconds per test run, tests use accelerated but representative lease and visibility intervals:

| Configuration Parameter | Production Value | Accelerated Test Value | Rationale |
| :--- | :--- | :--- | :--- |
| `lease_duration_seconds` | 30.0 s | 4.0 s | Allows lease expiration in < 5 seconds while giving renewal thread 2.0s cycles |
| `heartbeat_interval_seconds` | 10.0 s | 1.0 s | Guarantees fast failure detection upon worker process termination |
| `visibility_timeout_seconds` | 30.0 s | 3.0 s | In-flight Redis messages become reclaimable within 3.5 seconds |
| `reaper_sweep_interval` | 5.0 s | 1.0 s | The dispatcher reaper checks for stale leases and in-flight messages every second |
| `grace_period_seconds` | 15.0 s | 5.0 s | Ample time for active 1s tasks to complete during graceful shutdown |

### 3. Detailed Test Suite Specifications

#### Test Suite 1: `tests/reliability/test_graceful_shutdown.py`
* **Test 1.1: `test_graceful_shutdown_drains_active_tasks`**
  - Launch worker dispatcher subprocess with concurrency 2 and grace period 5.0s.
  - Enqueue 2 tasks with 1.5s execution duration (`sleep` handler).
  - Verify tasks are in `RUNNING`.
  - Send graceful shutdown signal (`SIGINT` or stop request).
  - Assert worker dispatcher halts with exit code 0.
  - Assert both tasks completed successfully (`SUCCESS` in PostgreSQL).
  - Assert 0 tasks stranded in `RUNNING` or `QUEUED`.

#### Test Suite 2: `tests/reliability/test_worker_process_crashes.py`
* **Test 2.1: `test_crash_point_2_pop_and_vanish_in_flight_reclaimed`**
  - Enqueue task with visibility timeout = 2s.
  - Subprocess pops message and is immediately terminated with `kill()` before lease acquisition.
  - Wait 2.5s for visibility timeout.
  - Run `broker.reclaim_expired()`.
  - Assert task returned to ready queue and successfully processed by replacement worker.
* **Test 2.2: `test_crash_point_3_post_lease_reaped_and_retried`**
  - Worker acquires lease and transitions task to `RUNNING`. Worker process is killed with `kill()`.
  - Wait for lease duration (4s).
  - Dispatcher reaper runs `recover_expired_leases()`.
  - Assert task transitioned to `RETRY_WAIT`, re-enqueued, and completed by replacement worker.
* **Test 2.3: `test_crash_point_6_post_result_duplicate_ack_safe`**
  - Worker computes task, commits `SUCCESS` in PostgreSQL, but is killed before calling `broker.ack()`.
  - In-flight expires; broker redelivers message to worker 2.
  - Worker 2 inspects PostgreSQL, detects task is already `SUCCESS`, logs idempotent skip, and calls `ack()`.
  - Assert exactly 1 result in DB, attempts = 1, queue empty.

#### Test Suite 3: `tests/reliability/test_heartbeat_failover.py`
* **Test 3.1: `test_heartbeat_loss_triggers_lease_theft_and_fencing`**
  - Worker A acquires lease for Task 1 with `lease_token_A`.
  - Worker A's heartbeat / renewal ceases (simulating crash or partition).
  - Lease expires. Reaper detects expired lease and re-enqueues.
  - Worker B acquires Task 1 with `lease_token_B` and completes to `SUCCESS`.
  - Worker A wakes up and attempts `update_status()` and `record_result()` using `lease_token_A`.
  - Assert Worker A raises `PermissionError` and is fenced. Worker B's result remains unmodified.
  - Log empirical latencies (`failure_detection_latency_ms`, `recovery_latency_ms`).

#### Test Suite 4: `tests/reliability/test_multiprocess_concurrency.py`
* **Test 4.1: `test_four_worker_processes_mixed_workload_under_chaos`**
  - Spawn 4 independent OS subprocesses running `WorkerDispatcher` (4 threads each = 16 execution slots).
  - Submit 1,000 mixed tasks (`noop`, `cpu_bound`, `io_bound`, `sleep`) across P0–P3.
  - Injected Chaos: Randomly terminate 2 worker processes mid-run, then spawn replacement worker processes.
  - Await completion.
  - Assertions:
    - Exactly 1,000 tasks terminal (`SUCCESS` or `DEAD_LETTER`).
    - 0 tasks stranded in `QUEUED`, `RUNNING`, or `RETRY_WAIT`.
    - Exactly 0 duplicate results committed.
    - Zero orphaned in-flight Redis messages.

#### Test Suite 5: `tests/reliability/test_execution_timeouts.py`
* **Test 5.1: `test_handler_completes_within_timeout`**
  - Enqueue task with `timeout_seconds = 3`, execution duration 0.2s.
  - Assert task transitions to `SUCCESS` in < 0.5s.
* **Test 5.2: `test_handler_exceeding_timeout_aborts_without_blocking_executor`**
  - Enqueue task with `timeout_seconds = 1`, handler sleeps 5s.
  - Assert `execute_task` returns `False` in $\approx 1.0\text{s}$ (does NOT wait 5s!).
  - Assert task attempt marked with timeout error and status is `RETRY_WAIT` or `FAILED`.
* **Test 5.3: `test_handler_infinite_loop_timeout_non_blocking`**
  - Enqueue CPU spinning handler (`while True: pass`) with `timeout_seconds = 1`.
  - Assert execution unblocks in 1.1s with timeout failure recorded.

#### Test Suite 6: `tests/integration/test_heterogeneous_workloads.py`
* **Test 6.1: `test_deterministic_workload_correctness_and_latency_profiles`**
  - Execute deterministic batches of `noop`, `cpu_bound`, `io_bound`, `sleep`, and `failing` handlers.
  - Verify deterministic output:
    - `noop`: `{"status": "ok"}`
    - `cpu_bound`: `{"primes_count": 1229}` for $n=10{,}000$
    - `io_bound`: `{"bytes_read": 1024, "status": "simulated_io_complete"}`
    - `failing`: `DEAD_LETTER` after 3 retries with complete stack trace history
  - Record P50, P95, and P99 latency distributions per handler type into `workload_correctness.json`.
