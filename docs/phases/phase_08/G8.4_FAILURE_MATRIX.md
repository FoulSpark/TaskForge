### 2. Concurrency & Persistence Failure Modes

| Fault ID | Category | Anomaly Description | Injection Mechanism | Detection Mechanism | Mitigation & Recovery Invariant | Required Final State | Test Suite |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **CF-01** | **Idempotency Race Condition** | Up to 1,000 parallel workers submit the identical idempotency key simultaneously | Multi-threaded / async concurrent `submit_task()` with identical key | PostgreSQL UNIQUE constraint on `idempotency_key` | First thread succeeds; remaining threads catch `(IntegrityError, SQLAlchemyError)`, rollback transaction, and fetch existing task | Exactly 1 task committed in DB; all callers receive identical task ID; 0 unhandled exceptions | `test_g84_idempotency_storms.py` |
| **CF-02** | **Idempotency Key Hijack / Collision** | Client submits an existing idempotency key with different payload or type | `POST /tasks` with reused key but conflicting payload | `_verify_payload_match()` in `TaskService` | Raises `IdempotencyConflictError`; caught by exception handler | HTTP 409 Conflict; original task unmodified; 0 duplicate tasks | `test_g84_idempotency_storms.py` |
| **CF-03** | **Multi-Producer Ingestion Contention** | 1,000 concurrent producers submit 10,000 tasks in a burst | ThreadPoolExecutor driving burst submissions against PostgreSQL | DB transaction throughput and lock contention | Atomic transactions with autocommit/session isolation | 10,000 tasks committed; 10,000 outbox events created; 0 dropped submissions | `test_g84_ingestion_storms.py` |
| **CF-04** | **Connection Pool Saturation** | Simultaneous active transactions exceed database connection pool limit | Configure `pool_size=10, max_overflow=20`, issue 50 concurrent long transactions | SQLAlchemy `QueuePool` saturation (`TimeoutError`) | Requests wait up to `pool_timeout`; callers handle timeout cleanly; no leaked sockets | Once load recedes, pool recovers to 0 active checked-out connections; subsequent queries succeed | `test_g84_pool_exhaustion.py` |
| **CF-05** | **Outbox Transaction Splitting** | Failure between task creation and outbox event creation | Atomic failure injection during `create_task()` | DB transaction boundary commits both atomically or rolls back both | Task and OutboxEvent are committed within the same database transaction | Zero orphaned tasks without outbox events; zero orphaned outbox events | `test_g84_persistence_audit.py` |
| **CF-06** | **Orphaned Relational Rows** | Foreign key mismatch between tasks and attempts, results, or events | Concurrent inserts and deletions | PostgreSQL Foreign Key constraints (`ON DELETE CASCADE` / referential integrity) | Direct SQL referential integrity audit | 0 orphaned attempts, results, or events | `test_g84_persistence_audit.py` |
